# Job Setup working rules

This is the separate preset-application plugin, not the hotbar sync engine. Follow README.md for the agreed product scope. Provide independent hotbar and Wrath application for the current class/job or all supported classes/jobs. Keep it distributable and usable without Hotbar Bridge.

Use the curated per-job source under ../wrath and its accepted constraints. Do not distribute personal settings indiscriminately, embed machine paths, silently overwrite other jobs during current-job operations, or invent Wrath runtime APIs. Verify action placement and configuration integration against installed compatible APIs. Stage and preview bulk writes, preserve backups, and report skipped/failed work accurately.

The plugin is implemented as an initial test release. Do not claim in-game validation from a successful build alone. Direct Wrath configuration-file replacement must be blocked whenever Wrath is enabled, including a final pre-write check. Base classes inherit corresponding job layouts by user decision; crafting and gathering now have twelve-slot, one-page presets with explicit omissions.

Automation variants use three independent user-facing switches: Auto burst, Auto mitigation, Auto job mechanics. Review behavior and hotbar changes case by case; switches can intentionally be no-ops on jobs already covered. All-on means maximum reviewed supported automation through button presses, not deleting unautomated abilities or enabling hands-free execution. Retain manual access for functions automation does not cover. Preserve the curated baseline when switches are off. All 21 combat jobs have individually reviewed variants; noncombat switches are documented no-ops.

Variant layout requirement: ST, AoE and gap-closer keyboard/controller assignments stay fixed, as do general tank and healer reserves (including Raise). Other keyboard functions compact in existing keyboard order through 1-4, then Shift positions. Only the general tank/healer reserves are pinned: situational Samurai/Reaper extras may compact. A job without a mobility action need not reserve an empty mobility position. Compaction is optional; off restores original spacing. Keep controller function positions stable. Do not delete functions outside automation coverage. Applying a layout updates Bridge's persistent effective per-job pair map and includes routing in complete layout backups. The editor's base map stays separate from compiled routes.

Experimental automatic Wrath management is explicitly requested by the user. It may use a fail-closed, signature-checked internal Dalamud adapter. Wait for completed unload before preview/write, retain loaded-state checks immediately before writing, restore only a Wrath instance unloaded by this operation, and report load/unload failures. Keep the option opt-in and manual installer access available. Compilation alone does not validate the lifecycle in game.

Preferred workflow: full initial setup while unloaded, then live variant switching through Wrath-owned commands for reviewed preset-only deltas. User explicitly authorized live settings updates. Verify effective and persisted state, preserve backups, and never bypass the unloaded-state guard for external file replacement. Changes to sliders, priorities, targeting or unreviewed presets retain the unload/reload path.

The user explicitly limits crafting/gathering/fishing to one page with twelve job slots. Do not add extra crossbar pages. Keep noncombat-hotbars.md to buttons tables and usage only; list omissions in noncombat-omissions.md and the per-class JSON sources. Preserve four shared utility slots. New action IDs must be verified against game sheets; CraftAction uses native slot type 9.

Automation selections are global: display exactly one set of three switches, independent of job and scope. The current/all scope determines which jobs receive those selections during preview/application. Do not store per-job switch choices. Job-specific behavior remains in preset definitions. Omission notes belong in documentation, not the plugin UI.

User-authorized macro commands may internally preview and immediately apply combined hotbar/Wrath variants for explicit current/all scope, without a separate UI approval click. Retain backups, readiness checks, failure rollback and reload policy. Show one global server-info entry using native mitigation/burst/job-mechanics icons; omit disabled icons and hide when all are disabled. Check the current job on class/character change and after application, using live Wrath preset states and saved custom values. Unapplied global choices must not change the active-job display. Per-job application outcomes may resolve indistinguishable no-op switches; these are history, never per-job controls. Hide an unknown status rather than carrying another job’s state.

Keep an internal canonical-job base-setup registry. Register only after successful Wrath preset application, never preview/hotbars-only/failure. Variant operations, including all-job macros and UI variant previews, must filter by registration; explicit base-setup operations may register new jobs. Status reads must return before inspecting Wrath for unregistered jobs. Migrate only actual application history, not matching settings. Full Wrath restore invalidates registration.

Variant operations must change only reviewed EnabledActionsV6 IDs, never re-merge baseline sliders, targeting, arrays or unrelated presets. Detailed preparation belongs to initial setup; revised preparation requires explicit revision refresh. Prepared switching always stays live while Wrath is enabled and may not auto-unload. Wrath saves are queued: wait non-blockingly for live plus persisted confirmation before committing hotbars; confirm rollback separately on failure.
